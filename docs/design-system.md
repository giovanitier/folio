# Design system

Folio uses vendored Syntari UI sources from `SyntariUI/syntari` revision
`ee2c15989c683f5ff7ec1d26d62505c7e3ff3b3e` (MIT).

- `public/vendor/syntari/app-shell.css`: application shell selectors from `patterns/app-shell.css`.
- `public/vendor/syntari/controls.css`: button, segmented control, search, field, badge, and table selectors selected from `styles.css`.
- `public/vendor/syntari/runtime/tokens.css`: selected palette, typography, spacing, radius, motion, and semantic tokens from `tokens.css`. Unused palettes, logo assets, and font-face declarations are omitted. Fonts fall back to the platform stack; no external font dependency is required.
- `public/styles.css`: application layout and chart styling. Overrides are scoped to `.folio-app` rather than changing upstream selectors.

The application is hand-composed from these components, not generated by the Screen IR runtime. Allocation comparison and overlap visualizations are Folio-specific extensions using Syntari tokens. Charts share a scale, include labels and keyboard-readable values, and are never populated from example data. There is no return or performance chart: quarterly reported values are not investment performance.

To update the vendored subset, review the upstream revision, selectors, and license, then run both application and browser tests. Avoid silently tracking upstream main or a third-party CDN at runtime.
